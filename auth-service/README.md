# auth-service

Identity for the whole system. Express + Better Auth + PostgreSQL. Signs in
users via GitHub OAuth, issues short-lived ES256 JWTs, and publishes the public
keys at a JWKS endpoint so every other service can verify tokens **locally** —
no call back to this service on the hot path.

## Stack

- Express + TypeScript (ESM)
- Better Auth (GitHub OAuth, session cookies, JWT plugin)
- PostgreSQL (Better Auth owns its schema here)
- Arcjet (bot detection + rate limiting on auth routes)

## How auth flows

```
Browser --GitHub OAuth--> Better Auth --> creates user + session cookie
                                      --> mints ES256 JWT on request (/api/auth/token)
                                          payload: { id, email, role }

Every API request --> Gateway --> fetches PUBLIC key once from /api/auth/jwks
                              --> verifies the JWT locally (no call here)
                              --> forwards to product/order/... with the claims
```

The private key is generated by Better Auth and stored in the `jwks` table. It
**never leaves this service**. The gateway only ever sees the public key.

## Key endpoints (all under /api/auth/*, owned by Better Auth)

- `GET  /api/auth/sign-in/social` — start GitHub OAuth
- `GET  /api/auth/callback/github` — OAuth callback
- `POST /api/auth/sign-out`
- `GET  /api/auth/token` — mint a JWT for the current session
- `GET  /api/auth/jwks` — **public** keys; the gateway verifies against this
- `GET  /me` — our own route: returns the current user or 401

## Setup

1. **Postgres** running and reachable via `DATABASE_URL`.
2. **GitHub OAuth app** (github.com/settings/developers):
   - Homepage: `http://localhost:3000`
   - Callback: `http://localhost:4000/api/auth/callback/github`
3. Copy env and fill it:
   ```bash
   cp .env.example .env
   # BETTER_AUTH_SECRET: openssl rand -base64 32
   ```
4. **Generate Better Auth's tables** (it manages its own schema):
   ```bash
   npm run auth:migrate      # creates user, session, account, jwks, verification
   ```
5. Run:
   ```bash
   npm install
   npm run dev               # http://localhost:4000
   ```

## Promoting the owner

Every user defaults to `role = 'customer'`. Your friend (the shop owner) needs
`role = 'owner'`. After they sign in once, run a one-line SQL update:

```sql
UPDATE "user" SET role = 'owner' WHERE email = 'friend@example.com';
```

Roles can't be set by users (the field is `input: false`) — only server-side.

## Note on keys (correction worth knowing)

An earlier plan had us generating an ES256 keypair with `openssl` and passing it
as env vars. That's **not** how the Better Auth JWT plugin works: it generates
and rotates the keys itself, stores them in the `jwks` table, and serves the
public set at the JWKS endpoint. No manual key files.
